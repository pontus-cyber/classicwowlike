# Balance report 2026-11-13b: autoplay's camp buys the Ember first (D134)

Status: measurement, draft for the Lead and the Lead Game Designer. No rules constant, content value, balance.md constant or spec was changed; src/ untouched.

**Verdict: keep (switch on).** On the same 600 seeds autoplay's Ember-first camp wins **25.5 %** against **18.0 %** for the old order (**+7.5 pp**, 3.5 - 11.5, paired) and reaches the boss **+6.7 pp** (3.1 - 10.3) more often. The gap to the planner's own camp falls from +11.5 pp to **+4.0 pp** (-0.0 - 8.0); the reach gap from +8.0 pp to +1.3 pp (n.s.). The planner's own camp does not read the switch: its records are run for run identical to report 2026-11-13 (720 / 720).

- **Engine measured:** main bade240 (rules engine of 3420b49, D133 / D134: `C.GATES.autoEmberFirst` on; otherwise the engine of report 2026-11-13).
- **Cell:** stage A of report 2026-11-13: planner P0 with `--prep-policy auto` (autoplay's start camp, the engine's `R.autoAction`; the planner everywhere else), `--map expedition --prep`, seeds 1000 on, the X0 tables, 200 per class (600 runs).
- **Arms:** on = as built; off = a cell naming every default-on switch but `autoEmberFirst` (`--gates rareHpMultZ1,firstMeetWindup,sapHold,passStealth,boardAcrossRun`, mark `-noae`); own = the planner's own camp (the default planner P0 cell) on the same seeds.
- **Simulator:** bade240 plus this change: the record field `emb` (Ember use: Ember resurrects, of them in the end-boss fight, Embers carried at the boss; written only in a run with one), `sim/samerecords.mjs --ignore`, `sim/measure-d134.sh`, `sim/d134report.mjs`. qa/sim 151 / 151.
- **Script:** `bash sim/measure-d134.sh sim/out/pass-d134 "E F I"` (4 min, 2 workers). Tables: `node sim/d134report.mjs`.
- **Pairing:** by class and seed; normal intervals on paired differences.

## Summary
1. **Win and reach.** On - off, paired: win **+7.5 pp** (3.5 - 11.5), reach **+6.7 pp** (3.1 - 10.3); boss win on reaching runs 24.7 -> 32.0 %. Every class gains: rogue 23.5 -> 27.5 %, mage 16.0 -> 27.0 %, hunter 14.5 -> 22.0 %.
2. **Ember use.** The Ember is bought in 100 % of runs and used: Ember resurrects per run **0.06 -> 0.95** (runs with one 5.7 -> 94.0 %), of them in the end-boss fight 0.05 -> 0.60 per run; 83.1 % of runs that reach the boss carry one into it (9.6 % before, vendor and elite drops). Resurrects from all sources 0.40 -> 0.97 per run.
3. **Contracts fall.** The Ember's points come out of the contracts: taken / completed per run **3.58 / 1.96 -> 2.36 / 1.29** (-1.22 / -0.67, paired); camp board 1.57 / 0.77 -> 1.35 / 0.69, hub 2.00 -> 1.00; Reserve left 1.55 -> 0.56; Field Draughts 100 -> 65 % of runs. Contract XP per run 124 k -> 49 k (contract XP share 8.8 -> 3.2 %). The resurrect is worth more than the contracts it displaces.
4. **Gap to the planner's camp.** Planner's camp - autoplay's, paired: before (switch off) win +11.5 pp (7.4 - 15.6), reach +8.0 pp; now (switch on) win **+4.0 pp** (-0.0 - 8.0), reach +1.3 pp (-2.0 - 4.7). The two camps now use the Ember alike (0.92 against 0.95 resurrects per run). What is left is contracts: the planner takes +0.42 and completes +0.31 more per run, with +77 k contract XP (camp board 1.75 / 0.93 against 1.35 / 0.69; it buys no Field Draughts) [inference: the residual gap is the contract difference; not split].
5. **The planner is unchanged.** The default planner P0 cell (600 runs) and planner PALL (40 per class) on this engine equal the cells of report 2026-11-13 run for run (720 / 720, every field but the wall time and the new `emb`). The off arm equals report 2026-11-13's stage A cell run for run (600 / 600): the switch off is the pre-D133 order, action for action. So every planner row of report 2026-11-13 (criterion 2, B39, B40, B42, B46, B10 ...) stands.

## Readings and known issues
1. **The win comes from the resurrect, and mostly at the boss.** 0.60 of the 0.95 Ember resurrects per run fall in the end-boss fight; boss win on reaching runs rises 7.3 pp, reach 6.7 pp.
2. **Autoplay's contract XP share is now low (3.2 %).** B46 (8-20 %) is a planner P0 row and still passes (8.3 %, report 2026-11-13); autoplay's camp is not held to it. Owner-facing: a player who leaves the camp to autoplay now completes 1.29 contracts per run instead of 1.96.
3. **Not run:** other classes of bot with `--prep-policy auto`, PALL with autoplay's camp, a Draughts-out-of-Reserve variant (engineer-2026-11-13 section 1), a no-Draughts variant.

## Levers and open questions (draft; for the Lead and the Designer)
1. **Keep `GATES.autoEmberFirst` on** (+7.5 pp win, +6.7 pp reach; planner rows unchanged).
2. Residual gap (+4.0 pp, interval touches 0): the candidate is contracts, not the Ember. The planner skips Field Draughts and holds 0.40 more camp contracts per run. Unmeasured candidate: autoplay's camp without Field Draughts (points into a further camp contract). Small; only if autoplay should match a planning player.
