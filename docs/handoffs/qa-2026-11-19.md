## 1. Causes and fixes
| Check | Cause | Fix | Where |
|---|---|---|---|
| SOUND "dimmingSpread sounds when kept" (part Q, step 49) | A check that depends on timing. The check drives Instant AUTO steps back to back; each takes about 3 ms on this machine, so the second near-player spread (14 steps after the first) came about 40 ms after it, inside RETRIGGER_S (50 ms), and the audio module dropped it by the retrigger rule (audio.md 3: correct). Seen in the log: dimmingSpread kept at t 13444, dropped at t 13484, nothing else kept in that step. Faster machines fail every time, which is why older builds fail too. Not a UI bug | The Dimming loop waits RETRIGGER_S + 20 ms before each step (imported from src/ui/audio.js), so the check tests the Instant rule and the sound, not the retrigger window | qa/browser/ui-regress.mjs part Q (6) |
| Y-1 "after a reload the refund note is gone" | A browser race, not the game. Headless Chromium sometimes starts a reloaded page with empty localStorage and sessionStorage. The game then sees no version 3 profile, migrates the version 1 profile again and shows the note again. Reproduced with a small script (load, reload, read storage at document start): 2 drops in 270 reloads, also with 0.5 s and 1.5 s waits before the reload. A key written from page.evaluate just before the reload is lost too. In the failing Y-1 run the reloaded page started with only the init script's keys (no v3 profile, no refund key) | `reloadKeep(page)`: writes a sentinel key, reloads, and if the sentinel is gone puts back the storage as it was before the reload (local and session) and reloads again (at most 3 tries). Y-1's "saw" says when this happened. Tested by forcing a drop on the first reload: Y-1 passes and reports the drop | qa/browser/ui-regress.mjs: Y-1 and the two S7 reloads (H05 hint store), which had the same risk |
