## 1. BUG-QA-12: the run end is stored when the run ends
- `engine-bridge.js` `storeRunEnd()`, called after every engine step (`apply`) and every dev op: when the run's state is in SUMMARY, it runs a dry END_RUN (the same one the summary's `meta.after` uses) and stores its `result.profile` (hero levels and XP, Legacy points, the welcome, the guide state), and logs the run in the run log. This happens in the step that ends the run (death, Abandon, the demo's end, a victory), before the summary is shown.
- The summary's button (END_RUN) then stores the same profile again and does not log the run a second time (`local.ended.logged`). The in-memory profile stays the pre-run one until END_RUN, so the summary shows what it showed before (balance before and after, "N unlocks within reach").
- "Play the guide again" in Settings while the summary is up puts the guide back on the stored run-end profile, and END_RUN keeps it (before, it would have stored the pre-run profile over the paid one).
- The run log is stored with the profile so `profile.runs` and the log's count stay equal after a reload on the summary (the hall would otherwise show "1 earlier run before the log").

## 2. Scene loop: paint on demand (map and fights)
- `Scene.frame(now)` still runs every animation frame and moves the scene's state exactly as before (the clock, ambient motes, actors settling on their marks, the scroll, the dim). In the modes `map`, `combat` and `boss` (`IDLE_MODES`) it paints the canvas only when:
  - `busy()`: an effect with a lifetime (particles, floats, projectiles, charge-ups, cores, rays, rings, slashes, the level-up pillar, a screen flash), the hit-stop, screen shake, the scroll, the dim, the backdrop cross-fade, an actor in a pose, a recoil, a hit flash, a death fade or walking to its mark, a prop sliding in; and the animations that carry meaning: a held telegraph (tremble and sparks) and the animated status marks (stun, burn, hex, sleep, off-balance);
  - `sig()` changed: one string of everything a paint reads besides the clock and ambient motion (mode, theme, backdrop, size, art style, target and hover rings, stealth, desaturation, boss phase, each actor's look, rank, flags, statuses and telegraph, the props);
  - `invalidate()`: a resize, a theme or Lantern art switch (onTheme).
- Not counted as running: the idle breathing, the rank glow, the drifting backdrop layers and the ambient motes. On a still map or between rounds the canvas keeps its last paint; the state still moves on (`coast()`), so the next paint is the one the old loop would have shown at that moment.
- Class select, the start camp, the hub, nodes and the summary paint every frame as before.
- `paint()` is the old frame body unchanged; `coast()` repeats only its state steps in the same order (motes, props, actors), and `moveMote` / `moveProp` are now shared by both, so the two cannot drift apart.
- Test hooks: `__ui.sceneFrames()` (`{ painted, coasted, mode, stale }`) and `__ui.paintScene()` (paints a stale canvas as it stands; no time passes).
- The Lantern switch path: switching `lanternArt` and `lanternTheme` at runtime on a still map and in an idle fight paints at once (painted 94 -> 97 and 203 -> 206, canvas changed, no console error; scratch check).

## 3. BUG-QA-13: not the game, the harness
- Heap snapshot after 4 runs (CDP, shortest retainer paths from the GC roots): 305 detached nodes; 232 of them held only by DevTools handles. The handle came from `qa/browser/demo/lib.mjs` `startRun`: `page.waitForSelector` returns an element handle that is never disposed, and each one kept that run's old hero select screen (the class card and its whole detached tree) alive. The other 73 are the scene's backdrop canvases (one set per theme) and the portrait cache: fixed-size caches, the same after run 1 and run 5.
- Window and document listeners were constant over the runs (CDP DOMDebugger.getEventListeners); no listener added at run start or screen build stays behind.
- Fix: `startRun` waits with `locator(...).waitFor()` (no handle). With it, nodes stay flat over 5 runs (956, 970, 1004, 971, 977) and the snapshot has 0 nodes held only by DevTools.
- No game code changed for this item.
