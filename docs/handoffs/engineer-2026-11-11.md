# Hand-off: Core Gameplay Engineer (with the UI side), 2026-11-11 (dev tools and the Dev menu)

## Summary
- Owner request (docs/feedback/2026-11-11-0741-owner.md) [stated]: in-game dev tools from a menu, so any stage can be
  tested without playing through.
- **Engine**: `R.debug` (src/engine/debug.js; docs/specs/engine-api.md section 12, a dev-only API, not game rules). It is
  pure and seeded, like `step`. Each run helper returns `{ state, events }` with a new state that passes
  `R.debug.validate`. Its input is never changed.
- **UI**: the Dev menu (src/ui/dev-menu.js), on by default in game.html. Press the backquote key (`, left of 1) or
  click the small violet DEV tab on the right edge, top corner. `?dev=0` hides it, and so does the "Dev tools" switch in
  Menu and settings. The mock engine (`?mock=1`) has no dev tools. Every button sends one op through
  engine-bridge.js to `R.debug`, and the UI holds no rules.
- **Dev runs**: a run that any dev tool changed is a dev run. Its summary is tagged "Dev run" ("· god mode" when god
  mode was on). It earns no Echoes and shows "(N withheld)". END_RUN leaves the profile as it was: no Echoes, no run
  counted, no boss flags or first kill. It is also left out of the run log. See Decision 1.

After each op, a toast and a combat-log line ("Dev: ...") say what changed. The result shows at once, like a loaded

## Decisions taken on a default (Lead or owner may change)
1. **Every dev tool makes a dev run, not only god mode.** The task named god mode. Without this, a jump to the boss
   would pay the boss and first-kill Echoes and set the profile's boss flags. To narrow it to god mode, change the
   condition in src/engine/summary.js (`dev`) and src/engine/meta.js (`applyRunToProfile`).
2. **God mode is a lasting IMMUNE that Final Dark does not pierce.** Because the player then loses 0 HP, a heavy blow
   counts as avoided (rules 7.13: OFF_BALANCE; 7.12: its wind-up answered). Wind-up tests should be done with god mode
   off. The pet still takes damage.
3. **Give talent points**: bonus points on top of the level's. They spend like earned ones and are counted in
   `talentPointsFree`.
4. **Reveal the map**: on the expedition map, every node of the current zone. On the rows map, Scout's Eye for the
   rest of the run, because that map hides only rare elites, traps and vendor Embers.
5. **Set hours**: moves the run's clock only. The expedition zone's Dimming stays where it was.
6. **Encounters**: at the player's level, with no elite level offset; the Level field changes it. The fight kind
   follows the strongest template (dboss, elite, trash or grind). There are no heat rewards. Won or fled, the player is
   back where the fight started (map, hub or Camp), and no map node is resolved.
7. **Jumps leave what is open, by the engine's own exits**: the loot window's items are dropped, a map node is resolved
   as after a flight, and a hub vendor's stock is kept.
8. **Start at gear**: fixed stats in every slot, like starting gear (the class's primary stat, STA, the power affix),
   at the chosen item level and rarity. Hours default to the line of the zone before ("on schedule"). The summary's
   heat chart starts at the built zone.
