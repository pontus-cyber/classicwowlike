## 2. Rescue loop (m3-onboarding.md 2.6, draft)
- Cause: `rescueEnd` spent ONB_RESCUE_TOLLS, which marks the settle step's Dimming check, so a rescue that landed on a Dimmed
  node started a Dimmed encounter in the same action; a death there was a rescue to the same node. Designer's case (guided
  onebutton Hunter, seed 1000, X0 tables, dm25): rescue at node 21 back to Dimmed node 9 (encounter at once, won), on to
  Road 19 (Roads still closed), then every rescue at 19 started the next encounter, one depth deeper; phase NODE until the
  20 000-action cap.
- Rule: the rescue's tolls (and the fight's) no longer count for the settle step, so the player lands with no node or fight
  open: phase MAP, or ZONE_HUB when the rescue goes back to the hub out of the Dimming (kept, as a walk there), or a dev
  fight's own phase. The next action is checked as usual (a walk onto a Dimmed node starts its encounter); a Bell that was
  ringing completes in the same step. The ONB_RESCUE_MAX-th rescue still pulls the player back, then ends the guide through
  the SKIP_GUIDE path: beats closed, Gorrak's node and the Roads open, no more rescues; event `guideSkipped` with
  `why: 'rescues'` and `rescues`; `profile.guide` `'skipped'` at END_RUN; the summary shows `skipped` with `rescues` 3.
  `tutorialView.rescueMax`. Content `guide.rescueCapLine` (draft): "That was the last rescue: the guide ends here, and from
  now on a death ends the run." (84 characters).
- After the fix, the same case: one rescue (step 70) lands on Dimmed node 9 with no fight; the bot rings the Bell (its
  encounter at 9 is won) and reaches zone 2; the run ends by death in zone 5 after 367 actions.
- Engine choices (draft, for the Lead): the hub visit after a rescue to the hub stays (no fight either way); the ringing
  Bell completes rather than being cancelled; the cap reuses SKIP_GUIDE, so `profile.guide` is `'skipped'`, not `'done'`.
