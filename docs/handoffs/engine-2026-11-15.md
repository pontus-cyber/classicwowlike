## 4. Findings
1. **Duplicate quests in every zone.** Node setup draws a zone's quest per node with repeats, so two nodes can name the
   same quest anywhere (the guided zone has Lost Lambs on 9 and 30, A Hermit's Debt on 11 and 17, Flour for the Crossing
   on 14 and 28; they show once the scripts are used up). Not changed: the draw changes every expedition run. Proposal:
   skip a quest already drawn in the zone while others remain, behind a switch, then re-measure.
2. **Weapon names have the offhand's problem.** The Agility weapon list mixes a bow and two blades for both Rogue and
   Hunter ("Yew Shortbow" for a Rogue). The class list now allows a content-only fix (`weapon.hunter`: bows); strict
   validation needs three names per list, so two more bows and one more blade per band. Not done (not asked).
3. **Guided nodes still change foes as the scripts advance** (the next script's enemies, at its level), only no longer
   their names. Binding the scripts to nodes would fix that and change the route (section 1, measured): for the Designer.
4. **The pace bound can read 4 in the guided zone before the release** (a skip at the right toll can dim two corridor
   nodes with two scheduled ones). It is true, and above what any measured route shows (3). If the Lead wants the
   tooltip to read 2 there, the alternative is a rule change: the corridor's release keeps the cap (guided runs change).
5. **Autoplay's guided route (Mage, seed 5) shows no growing cost** on an unresolved node: the 3-to-5 case of item 5
   needs a slower route, as the tester's; s21 builds it by moving the clock next to node 4.

## 5. UI needs (UI/UX Engineer; src/ui; every line draft)
1. **Guided quest nodes (item 1).** An unresolved Quest node with `guided` has `title: null`: show no quest name there
   (the tooltip's "Ring 1 · guided fight" already says what it is). If a name is wanted, say it is the guide's next one,
   not the node's: "The guide's next fight: {quest}, on the first of these you enter" (quest from `tutorialView.next`
   and `CONTENT.tutorial.scripts[i].quest`). The node being played and done nodes keep their `title`.
2. **Level-up banner (item 2).** director.js `levelUp`: build "New at the trainer" from `R.trainerView(state after the
   step, e.level)`, not `next.trainer` (engine-bridge.js can add it to each converted `levelUp` event, line ~1256, where
   it already builds `newSpells`). The hub card keeps `trainerView(state).next`.
3. **Gorrak's node (item 3).** screens.js `expNodeTip` (and the node's aria-label): title the node by `n.name` when
   present, before NODE_NAME and before "Unknown" (his node has it while unseen too). The gate line is content: no code.
4. **Dimming tooltip (item 4).** Nothing: `{maxPerToll}` now holds for the rest of the zone. `dim.cap` is there if the
   tooltip should name both ("2 a toll, 3 while the road's lamps go out").
5. **Toll parts (item 5).** Where a toll cost shows (the node label, "Costs N tolls"), when `parts` has a 'dimFight' part:
   "Costs 5 tolls: 3 for the quest, +2 for a fight in the Dimming (it dims before you finish)"; with `escape`: "+1".
6. **Talent window (item 6).** windows.js line 185: `CONTENT.texts.progress.talent_points` / `talents_locked`, {first} =
   `C.TALENT_FIRST_LEVEL`, {step} = `C.TALENT_LEVEL_STEP`, and the test `p.level < C.TALENT_FIRST_LEVEL` in place of 10.
7. **Offhand icon (item 7, optional).** The offhand icon is a book for every class; a quiver for a Hunter's Agility
   offhand and a shield for any other Agility one would match the names.
8. **Carry (item 8).** The Furnace tooltip (heat.js `heatTip`), at least in a zone's first tolls: "Tolls carry over: this
