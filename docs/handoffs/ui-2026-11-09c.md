# UI/UX & Visual Engineer hand-off, 2026-11-09c (UI for M2 v2)

## Summary
- The UI follows the M2 v2 engine (3559e0e): 7 rows, travel on one level early, Linked per Shard, elite offset 1, par 120 h. No row or lane count and no other rule number is left in UI code; texts read the engine's constants through `data.rules` in the bridge, the map counts its rows and lanes from `mapView`.
- Round time budget (rules 3, changes-m2-v2.md rows 51-52): at the default speed (1x) a combat round is on screen for at most PACE_ROUND_ANIM_S (1.5 s, read from the engine). Any input during the animations finishes them at once. 2x, 4x and Instant still work and are each faster.
- Checks on the final source (a7efdaf, build of src/ identical to 9b39bf8): qa/browser/ui-regress.mjs 86/86 at 1366x768 and 1920x1080, qa/browser/ui-checks.mjs 8/8 at both sizes, tools/ui-check.mjs clean in engine and mock mode; 0 console errors, 0 page errors, 0 requests.

## Notes for the team
- Engineer: the bridge copies one rule formula, Linked = min(LINK_DR, LINK_DR_PER_SHARD × n), in `rulesTable` (engine-bridge.js), because the engine's `linkedDr` is internal. Exporting it (or `dr` on the boss in state) would remove the copy. Default until then: the copy, read from the constants.
- QA: pace.mjs always presses key 1; for a Rogue, slot 1 is often refused and counts as a round of about 30 ms, which lowers the median [inference: diag run of this session, rogue rows of 25-47 ms]. ui-regress part D presses the key of the autoplay policy's choice instead and skips refused presses.
- Designer: autoplay rounds also play within the round budget, then wait `autoDelay` (350 ms at 1x), about 1.6 s per autoplay round at 1x, 0.85 s at 2x, against PACE_AUTO_ROUND_S 0.8 [inference: part D medians plus the autoplay delay; not measured with autoplay].
- Changes row 54 (quest enemy count on the map) was done in ui-2026-11-09b (tooltip "Foes: 2 enemies (2 × Caster)"); its check still passes.
