## How to build and open
```
node tools/build.mjs                  # src/index.html -> dist/game.html (dist/ is git-ignored)
node tools/build.mjs --out game.html  # release build to another path (the Lead owns game.html)
node tools/build.mjs --watch          # rebuild on every change in src/
node tools/build.mjs --serve 8080     # serve src/ unbundled (ES modules do not load from file://)
```
Open `dist/game.html` in a browser (double-click works). URL options:
- `?seed=1234` fixed run seed (otherwise the UI draws a random seed for each run).
- `?mock=1` use the mock engine instead of the real one.
- `?speed=2` start at another animation speed (1, 2 or 4; 0 or `instant` skips animations).

The builder is documented at the top of `tools/build.mjs`: it keeps ES-module semantics (evaluation order, live bindings, cycles, `export *`, `import.meta.url`, literal `import()`), stays inside `src/`, and fails with a clear message on bare specifiers, missing files or exports, and syntax errors in the bundle.

## Real engine and mock
- `src/ui/engine-bridge.js` is the only UI file that imports the engine. It reads state (`newRun`, `legalActions`, `whyIllegal`, `mapView`, `spellInfo`, `fleeChance`, `itemScore`, `xpToNext`, the `C` tables) and sends actions (`step`, `autoAction`). It turns engine state into one view object for the screens and engine events into animation events.
- No game rules in UI code: costs, cooldowns, legality, flee chance, map paths, damage estimates, hours per node and bag size all come from the engine. The bridge adds presentation-only pauses that do not change engine state: quest/elite/dungeon/treasure intros, the spoils window after a victory, the rest screen and the closed chest. Autoplay passes them.
- The meta profile (Echoes, unlocks) that the engine returns at run end is kept in `localStorage` (`tbwcr.profile.v1`) and passed to `newRun`.
- Mock: `src/ui/mock-engine.js` and `src/ui/mock-data.js`, only used with `?mock=1`. The mock's numbers are rough and not balanced; its debug jumps work only in mock mode.

## Known issues and notes
- No screen to spend Echoes yet. The summary shows what was earned; the profile is saved and used by the next run.
- Spell tooltips show `spellInfo` amounts, which are before level difference, crits and the target's defences (the tooltip says so).
- Out of combat, energy and focus show a full 100 because there is no fight state to read; the true values appear when a fight starts.
- `rules.js` does not export `bagCapacity`; the bridge shows `C.BAG_SLOTS + state.meta.bagSlots`, the same sum the engine uses. An exported helper would remove this copy.
- Quest givers, merchants and trainers use the generic humanoid figure with different clothes.
- Headless Chrome with software rendering draws the map screen at about 30 fps at 1920x1080 (60 fps at 1366x768). Not measured on a machine with a GPU.
- The headless deep run uses autoplay at instant speed, so a few screenshots show floating numbers from the previous rounds.
