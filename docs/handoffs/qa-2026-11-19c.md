## 3. Autoplay takes quests far above the hero (for the engineer; no engine change made)
**Where the rule lives:** `src/engine/autoplay.js`, `nodeScore(s, node)`, line `case 'quest': return S.quest;`. Elites and
dungeons are gated on the player's power level (`p.level >= node.eliteLevel - AUTO_ELITE_LEVEL_SLACK`, and `node.trashLevel -
AUTO_DUNGEON_LEVEL_SLACK`; otherwise they score `S.risky` and `expScore` returns null). A quest has no gate. Its level is
`node.cl` (expedition.js `setupExpNode`: the zone's band fixed at arrival + ring base [0, 0, 1, 2] + spread 0-1 + a quest
offset -1..+1), so in a Legacy run, where the band is set from the power level at arrival and the hero then levels in the
zone, a ring-3 quest can sit far over the hero. Seed 7: the zone 6 ring-3 quest is at power 15 against power 8. Quests also
carry no HP or draught check (the elite gate has `AUTO_ELITE_HP`).

**Suggested fix** (a Legacy run only; a level-60 run keeps rule 1.9.9):
```js
case 'quest': return isLegacy(s) && p.level < node.cl - EA.AUTO_QUEST_LEVEL_SLACK ? S.risky : S.quest;
```
with `AUTO_QUEST_LEVEL_SLACK: 3` in the AUTO table beside `AUTO_ELITE_LEVEL_SLACK`. `expScore` then skips the quest and the
policy goes on to the next node or leaves (the same as a risky elite). An unseen node is still walked to, because the
target test for unseen nodes does not read the level (exploreStep); the gate acts once the node is seen. An HP gate
(`hpF >= AUTO_ELITE_HP`) is optional; a draught condition is not needed once the level gate holds.

**Evidence** (Node, not the browser: engine autoplay in every fight, qa/browser/policy.mjs, Economy v2 and Oruvath rules
on, profile runs 2, expedition map, seeds 1-40 per class and level; the patched copy lives in /tmp, nothing in the repo).
