# Content hand-off 2026-11-11 (Content Designer)

Status: draft. Content is written and checked, but NOT pushed to main: it needs two small engine changes first (section 3).

## 1. Added
- `texts.families` (src/content/texts.js): `{ singular, plural }` for all 18 family ids (outlaw, wild, blight, fenbeast, reedfolk, witchkin, crag, reiver, stormward, tomb, dune, sunbound, rootkin, grave, veil, cinder, forgeborn, pyrecult).
- `texts.prep`: for each of the nine prep ids `{ name, flavour, rule }`. `name` repeats `C.PREP_OPTION[id].name` as a name check. `rule` has no numbers (counts and prices are constants and may change).
- `texts.contracts`: templates `cull`, `bounty`, `delve`, `hub`. Placeholders: `{n}` `{family}` (plural) `{familyOne}` (singular) `{region}` `{zone}` `{levels}` `{elite}` `{dungeon}` `{hub}` `{contract}`.

## 2. Guesses
- The shape of `texts.families` (object with singular and plural) and `texts.prep` (object with three fields); the engine proposal did not fix it.
- Rare archetypes: the caster-like families (witchkin, stormward, sunbound, veil, pyrecult) got the mender archetype because every zone's elites already use brute and caster. That is six menders across the game; the Designer may want to vary them.

## 3. Blockers (why this is not on main)
1. `CONTENT_RANGE.rares` in src/constants.js is [1, 2]. Each zone now has 3 rares (z1 to z3 had 1 and gained 2; z4 to z6 had 2 and gained 1), so strict validation fails. Needs `rares: [1, 3]` (the Designer owns the number).
2. `validateContent` (src/engine/content.js) rejects `texts.families`, `texts.prep` and `texts.contracts` as unknown groups, and checks every text as a string. Needs the three groups added to `known` (ids: the family ids from the enemies, `PREP_OPTION_IDS`, and `cull|bounty|delve|hub`) and a check that accepts the object shapes above (or a flatter shape if the Engineer prefers; tell me and I will change it).
Both are outside src/content, so I did not touch them.

## 4. Checks
- With both changes applied only in a scratch copy (reverted afterwards): `validateContent(CONTENT, {strict: true})` returns no errors; `node --test qa/engine/ qa/rules/` 433 of 433 pass; `node --test qa/docs/ qa/sim/` 90 of 90 pass.
- Without them: strict validation gives exactly 9 errors (6 zones with 3 rares, 3 unknown text groups) and no others.
- Golden changes: none. No golden test moved, so no engine test was edited.
- Existing contracts logic (src/engine/contracts.js drawOffer) already filters a Bounty's rare by family, so the new rares are picked for their families without further changes.
