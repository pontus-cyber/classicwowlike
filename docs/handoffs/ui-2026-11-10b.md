# UI/UX & Visual Engineer hand-off, 2026-11-10b (M3: Hall of Echoes)

## Summary
- New between-runs screen, the **Hall of Echoes** (src/ui/meta.js). It lies over class select. Two ways in: "Spend Echoes" on the run summary (END_RUN stores the profile, then the Hall opens) and the Echoes button on class select (balance, and a badge with the number of unlocks within reach).
- It shows the balance (earned and spent), a run log, and the engine's catalogue (`R.metaOffers`), grouped by the kinds of rules 11.2. Each card has the name, an effect text built from the catalogue entry (`R.C.META`), rank/ranks, the next cost and a state: owned, affordable, too few Echoes, or locked (with what it needs). Buy sends the new bridge action `META_BUY`. The bridge calls `R.buyMeta`, saves the profile in localStorage (inside try/catch) and rebuilds the run being created with the new profile, so START_RUN applies the unlock.
- Purchase feedback: the balance counts to the new value and the difference floats up. The card flashes gold, the new rank pip pops, and the matching "Your next run" line lights up. Unlocks that just opened (for example Alchemist's Notes after Packed Satchel) shimmer. A line says what was learned and what changes next run. When the Hall opens after a run, that run's Echoes count in ("+8 Echoes from Hunter's run").
- "Your next run" lists the engine's run modifiers for the chosen class, read from a dry START_RUN (`state.meta`, bag, weapon, Oath multiplier).
- Oaths: once the profile owns them, class select shows one switch per Oath with its effect. The switches send `SET_OATH`, and the panel shows the Echo multiplier the engine computes. The run summary now shows the Oath line (×1.5) between the Echo lines and the total.
- Tooltips on every new element; Esc closes the Hall.
- One extra fix that buying Wayfinder made visible: the map's "Travel on" tooltip read "Costs 2 h" even with Wayfinder owned. It now reads the hours from a dry TRAVEL_ON step.
- Checks on the pushed source (cf3afff): `qa/browser/ui-regress.mjs` 140/140 (70 per size; 15 per size are the new part F). `qa/browser/ui-checks.mjs` 8/8 at 1366x768 and at 1920x1080. 0 console errors, 0 page errors, 0 requests.

No rule is copied into UI code. ## Notes for the team
- Engineer:
  1. The profile has counts, not records, so the per-class best level, furthest place and kills live in the UI's run log (localStorage). If these should travel with the profile, or the sim should use them, a `profile.log` written at END_RUN would replace the UI log.
  2. `metaOffers` returns `req` ids but not which of them are met. A `reqMet` list there would remove the tooltip's own reading of `reachedBoss` and `bossKills`.
  3. The camp panel's "par" is `C.BOSS_TIME_PAR` and ignores the Oath of Haste. The Ascendancy shown next to it is right (dry FIGHT_BOSS). A `bossPar(state)` export would fix that line without a rule copy.
- Designer (v4 pass): ranks, costs and per-rank effects show from the engine with no UI change. A new effect field, a new kind or a new requirement flag needs one line in src/ui/ui-text.js (`metaEffect`, `META_KIND`, `metaReqText`). Without it, the card falls back to the kind name and the shortest column.
- Lead:
  1. END_RUN now starts the next run on the same class and pet (not the same name).
  2. The summary has two exits: "Spend Echoes" (primary) and "Begin a new run".
  3. Mock mode has no profile, so there is no Echoes button, no "Spend Echoes" and no Oaths.
- QA:
  1. Part F picks its seed at run time, so a balance change moves the seed instead of breaking the setup.
  2. `tools/ui-check.mjs --mock` fails at the hub on main (before this work too). In the mock, after the hub trainer's Done, no Vendor card is found.
