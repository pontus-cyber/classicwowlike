## 4. Interpretations (draft: please confirm or change)
1. **`src/index.html` not touched.** It is outside the paths this task may commit, so tokens.css comes in through
   `@import` at the top of style.css and the builder inlines it (tools/build.mjs is the Lead's file; the change is the
   `inlineCss` helper and one call). If the Lead prefers a `<link>` before style.css in index.html, remove the `@import`
   line and the helper can stay.
2. **"current" is also the default.** The block is `:root, :root[data-theme="current"]`, so the game needs no attribute
   on `<html>`. The proof slice's Dev switch sets `data-theme="lantern"` on `<html>`; its block (higher specificity)
   then overrides only the tokens it sets.
3. **One value, one token.** Each token has its own value; two roles never share a token value, so a theme can move
   one role without the other. Where style.css uses one exact value for two roles outside the role-filtered groups, it
   got the token of its main role. The ones the art slice should look at: `--danger-lethal` (#ff6a6a) is also the map's
   urgent "dims in N" clock; `--ink-paper` (#3a2a16) is both parchment text and the map's node rings; `--accent-hi`
   (#ffd36a) also marks reachable map nodes and the elite portrait; `--ink-bright` (#fff) also the Shardfall key on the
   map. `#ffffff` (4 uses) is left as a literal beside `--ink-bright: #fff` (different text, same colour).
4. **Groups beyond the list.** "edge and shade" (frame lines, the black line and shadow ramp `--shade-NN`, gold line
   ramp `--edge-hi-NN`, white glints) and "resource bars" (the existing `--hp-*`, `--mana-*`, ...) are their own groups.
   The only school colours in CSS are frost's (the FROZEN window); the other schools live in JavaScript (R3).
5. Three moved variables were unused before and still are: `--gold-2`, `--edge-lo`, `--rested`.
