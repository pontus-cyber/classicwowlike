## 3. Item 4: rule, identity and balance
- Rule (rules 8.3, draft): an item rolled on a "choose one" reward table (`C.REWARD_DROP_TABLES`: quest, story, contract,
  bounty) takes the class's primary at `C.REWARD_CLASS_BIAS` (1.0: always) instead of DROP_CLASS_BIAS (0.70), while
  `C.GATES.rewardPrimary` is on (default; sim tag `rp`, the old arm `-norp`). The primary draw is made either way, so the
  loot stream does not move; kill, elite, treasure and vendor items keep DROP_CLASS_BIAS. Seeded and pure.
- Identity, non-guided runs: with the switch off, everything before D144 holds: the s18 golden hashes of 25a8879 (18/18
  runs), and the sim run for run, 1500/1500 runs identical with 1ce100b's engine (`sim/samerecords.mjs`; cells greedy,
  planner, speedrunner and onebutton on the expedition with the camp, greedy on the classic map; 3 classes x 100 seeds
  from 101; `--profile fresh --warmup 0`). As built (on): 619/1500 identical; the 881 others met a reward that drew the
  other primary. Items 1-3 and 5 change no non-guided run.
- Balance (planner P0, expedition with the camp, 500 seeds per class from 1000, `--warmup 0`, paired): win 14.2 % ->
  18.1 % (rogue 11.8 -> 17.6, mage 17.6 -> 21.0, hunter 13.2 -> 15.8; +122 / -63 runs), boss reached 38.8 % -> 41.3 %. The
  100-seed identity cells mostly agree (win, rogue / mage / hunter: planner -1 / +4 / +10 pp, greedy on the classic map
  +2 / +5 / +5 pp; the other cells win at most 1 % in either arm). For the Sim and the Designer: measure it in the
  standard tables (B-targets); REWARD_CLASS_BIAS is a draft value (e.g. 0.85-0.9 would shrink the effect), and zone 1 was
  already found too easy.
- Not changed: kill drops can still carry the other primary (30 %). The UI's "Upgrade" arrow follows itemScore, which
  scores the wrong primary 0 but STA, armour and weapon damage normally, so an Intellect weapon with more weapon damage
  can still be a real upgrade for a Rogue (the casual's "Elm Switch"). With this change no reward offers one.

## 4. For the UI (src/ui is not mine)
1. **Hub welcome (item 2a):** director.js:171 logs "Welcome to <zone>. Visit the trainer, then set out." on every hub
   arrival. Use content `T.guide.hubTrainerLine` while `R.trainerView(state).useful`, else `T.guide.hubLine` (`{zone}` =
   the zone's name). At the first hub every class gets `{ learn: [], train: [], next: 4, useful: false }`. Optional: the
   hub's Trainer card (screens.js:269) and a Trainer node's tooltip could say "Nothing new to learn (next spell at level
   N)" when not useful.
2. **H05 (item 2b):** when the off-balance enemy has `offBalance.absorbs`, show `H05.shield` (content `alt.shield`)
   instead of H05's line. onboarding.js `rawLine` reads `alt` only for beats and `sameAs` hints: hints need
   `x.alt[key]` too. Suggestion: leave H05 unseen after the shield line, so "spend your big hit" is still taught in a later
   unshielded window. The casual's case: Bargh (level 18, 872 HP) with a Bolster shield of 174 against a level 10 Rogue
   whose main hit in the window is about 34: `{ shield: 174, absorbs: true }`.
3. **"WIND-UP R3 null" (item 3):** not in the engine view. tracks.js:322 `box.append(h('span.wu-b', ...), lethal ?
   lethalBadge() : null, h('span.wu-t', msg))`: the native `Element.append` turns `null` into the text "null" (util.js
   `h` and `add` skip it). Use `add(box, ...)` or drop the null.
4. **G9 "turn 2" vs "round 3":** done in content (no turn number; the badge shows the round). `num.deathblowTurn`
   (engine-bridge.js:380) is no longer used by any line. If the line should name the round, add `deathblowRound:
   C.SIGNATURE_TURN + 1` to that num map first, then the content can say "in round {deathblowRound}".
5. **Elite tooltip "one level higher":** screens.js:61 `nodeDesc('elite')` uses ELITE_LEVEL_OFFSET (above the node's
   content level), and the tooltip header (screens.js:730) shows `n.cl`. The elite fights at `mapView` node `level`
   (cl + 1); show that, and the gap to the player's level.
6. **Chest loot logged before "Open the chest":** the engine opens an unguarded chest on entry (rules 2.8). The bridge
   holds the chest (engine-bridge.js:1468) but returns the step's gold, trap and loot events at once, so the log shows them;
   keep them back and emit them on OPEN_CHEST (engine-bridge.js:1344).
7. **"You flee from the fight." twice:** the bridge turns both the engine's `action { kind: 'flee', success: true }`
   (engine-bridge.js:1124) and `fled` (engine-bridge.js:1207) into `{ t: 'flee', ok: true }`; director.js:377 logs each.
   Keep one (e.g. `fled` for a success, the action event only for a failure).
8. **Grind "Wave 1: 1 enemy" / "1 to 3 waves of two enemies" vs "Wave 0 of 1":** the description uses the classic
   map's GRIND_MAX_WAVES (3) and GRIND_WAVE_SIZE (2) (rulesTable) on the expedition map; `mapView` grind nodes now give
   `waves` (EXPED_GRIND_MAX_WAVES, 1) with `archetypes` (wave 1). The tracker (hud.js:782) prints `waves` (waves done, 0
   in the first wave); show `fightNo` during a fight.
9. **Quest tooltip "Ring 3 · levels 8-10" vs "Level 5":** in the guided zone a scripted fight is capped at
   ONB_SCRIPT_LEVEL_MAX (5) by design. `mapView` now marks such nodes `guided: 'script' | 'site'`. Show the ring's band
   only while the node's own level is unknown, and e.g. "Guided fight" on a `guided` node.
10. **Contracts "1/4" then "0/4":** prep.js:294 prints held/slots; a completed contract frees its slot, so held drops.
    Label it as slots ("1 of 4 slots") or add the completed count (contractView `status: 'complete'`).
11. **Hit chances (item 5):** `windupView` answers now carry `chance` where a hit roll decides (Rime Burst, Deadfall
    Trap); tracks.js shows those answers with "?" / "(a chance)": show the number ("Rime Burst 91 %"). `spellInfo(...)`
    gives `hit` (single target) and `hitAll` (AoE, per enemy) for tooltips (tactician: "hit/miss chance shown nowhere").
12. Related, not asked: Pre-cast Rime Burst in the engage round freezes for 1 round, which ends before any enemy acts
    (tactician s0164); `engagePreview` already shows no cancelled turn for it. The engage panel could say so.
