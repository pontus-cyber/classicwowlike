# UI hand-off 2026-11-14e: blind round 2, the UI bugs and friction

Role: UI/UX & Visual Engineer. Status: **draft**. Every new player-facing line below is draft wording, not yet approved by
the owner. Sources: the bug sections of docs/feedback/2026-11-14-blind-casual-rerun.md, -tactician-rerun.md, -skipper.md,
-competitive.md and -explorer.md; D150 (word budgets) and D151 (not implemented here: its designer spec is being written
in parallel) [source: docs/DECISIONS.md]. No file in src/engine or src/content was touched. game.html and dist/ were built
only to run the checks and are not committed.

How each item was reproduced: ui-regress part U (new) was run on the build before this work (17cbe11) and on the build
after it. Before: 11 of 32 checks passed. After: all pass. Every item marked "fixed" failed its check on 17cbe11, except
where the table says otherwise. Scratch scripts in /tmp/scr (outside the repository) were used for the first looks
(screenshots, overlap counts on 74 map states over seeds 7, 11 and 8736).

Test changes that follow the new behaviour:
- Part E plays the boss fight on autoplay through a revive. Autoplay now stops after the revive, so the part presses Z again, and a new check counts the stops against the engine's revives.
- Part U waits for a toast that may sit in the stack's queue (up to 7 s), and reads the four nameplates once the enemies stand still after walking in. While they walk in, the names can touch by 2 to 3 px for under a second.
- full-run switches autoplay back on with the toggle when the game turns it off: at a fight in the Dimming, or after a revive mid-fight. It clicks "Equip now" in the loot window. It expects "Face the boss" at the expedition dungeon's last trash fight. It plays the twin's last autoplay fight when the run ended before the loop came round.
